# 寓言讲概念 · Skill 包

把一个抽象概念藏进一个具体场景里，让读者读完"懂了"，却说不出术语。

**核心纪律：读者应该能复述机制，但说不出名字。** 说出名字的那一刻，寓言就失效了。

## 这个包解决什么

讲抽象概念有两种失败方式：

- **直接讲术语** —— 读者记住了名词，没抓住机制，换个场景就不会用了；
- **滥用比喻** —— "这就像……" 一句带过，读者点头然后忘光。

这个技能走第三条路：**先写出一个具体的场景，让机制自己显形，术语留到第二部分才出现**。读者读完能复述"发生了什么"，你才告诉他这叫什么。

## 交付三段式

1. **寓言正文**（≤1000 字）—— 全程不出现概念名与领域术语
2. **概念解析** —— 流派、定义 + 故事元素**逐一映射**（落到具体动作，不写"象征了复杂性"）
3. **两个检验问题** —— 理解检验（换掉设定机制还成立吗）+ 迁移检验（搬到新场景会在哪一步出现）

## 包结构

```
fable-concept/
├── SKILL.md                    # 概念拆解、场景选型、结构与节奏、交付格式
├── references/
│   ├── craft.md                # 概念→场景详细手法、转折六种处理、常见失效模式
│   ├── checklist.md            # 完整自检清单（硬规则 + 软规则）
│   └── examples.md             # 一个合格范例 + 一个失败范例
├── scripts/
│   └── lint_fable.py           # 自动自检脚本
└── README.md
```

**纯 Python 标准库实现，无需 pip install 任何东西。**

## 使用方式

在 WorkBuddy 对话中直接说：

```
用寓言讲清楚复利这个概念
把沉没成本写成一个故事，别出现术语
用比喻说明边际效用递减
```

技能会先在草稿区拆解概念（机制/触发/代价/边界），再动笔，最后跑 lint 自检。

## lint 脚本用法

正文文件顶部加一段隐藏注释声明角色与概念（注释不参与正文输出）：

```
<!-- fable-lint
cast: 母猫, 小孩
concept: 边际效用, 效用递减
-->
```

```bash
python scripts/lint_fable.py 输出.md          # 人读的报告
python scripts/lint_fable.py 输出.md --json    # 机器读
python scripts/lint_fable.py 输出.md --strict  # 有 WARN 也算失败
```

脚本检查：字数、角色数、意象黑名单、过度文艺化地名、结构套路（智者点拨/异象顿悟/孩童点醒/师徒辩难/临终遗言）、角色黑名单、开头黑名单、概念术语泄漏，以及可替换替身意象（提示级）。

> **脚本只挡机械问题，挡不住"故事其实没意思"。** 脚本 PASS 不等于合格，仍要人读。

## 打包

```bash
python build_release.py src/fable-concept dist
```

产出 `dist/fable-concept.zip`，可用于 WorkBuddy 开放平台上传。
